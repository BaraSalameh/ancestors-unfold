# Business-rule matrix

This matrix records the behavior enforced by the application, database, and tests. It is a
characterization of the current product contract, not a source for inventing genealogy policy.

| Capability                   | Current rule                                                                                                                                                                                                                          | Enforcement and evidence                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Authentication               | Only active users with a live, non-revoked idle and absolute session may access authenticated APIs. Incomplete profiles can only finish profile/session operations.                                                                   | `features/auth/server/session-service.ts`, `server/api.ts`, database smoke tests     |
| Tree ownership               | A tree has one canonical owner. Owner-only collaboration resources are omitted for contributors.                                                                                                                                      | migrations 014 and 020; dashboard bootstrap service; owner/contributor tests         |
| Tree visibility              | Anonymous snapshot preview is allowed only when `visibility='public'`. Private trees require an authenticated membership/grant.                                                                                                       | `trees/server/snapshot-reader.ts`, `snapshot-public-reader.test.ts`, RLS smoke tests |
| Affiliations and grants      | Revoked or expired memberships cannot make a tree visible. Branch grants are independently expiry/revocation checked and only expose the assigned branch plus permitted unattached drafts.                                            | migrations 015 and 036; `snapshot-reader.ts`; database role checks                   |
| Invitations                  | Invitations bind an email, existing family member, and branch. Cancelled, expired, mismatched, already-used, and already-registered invitations cannot provision access.                                                              | invitation/registration services, Zod invitation schema, migrations 012 and 036      |
| Ownership transfer           | Only a pending, unexpired transfer may proceed. The current owner verifies a short-lived code; only the proposed owner may accept. Acceptance serializes ownership/membership/grant changes.                                          | `ownership-transfer-handler.ts`, migration 020                                       |
| Contributor removal/deletion | Owners cannot use contributor-account deletion. Contributor removal requires a short-lived verification challenge and reconciles grants, membership, invitations, and linked identity atomically.                                     | collaboration policy and removal handlers; migrations 021–023                        |
| Member editing               | Snapshot inputs are schema validated, writes are authorized to full-tree or branch scope, and protected branch roots/import mappings cannot be silently changed or deleted.                                                           | tree snapshot schemas, delta validation, branch-root/import protection tests         |
| Member deletion              | The client produces an explicit deletion plan, separates protected members, and asks separately about eligible wives. Persistence revalidates scope and referential rules.                                                            | `members/domain/member-deletion.ts`, snapshot validation tests                       |
| Parents and spouses          | Parent roles are unique, reciprocal spouse state is normalized, and parent pairs can be reconciled as spouses. Hidden branch relationships are removed from scoped snapshots.                                                         | relationship domain tests, relationship writer tests, snapshot projection tests      |
| Cycles                       | Parent ancestry cycles are rejected both before snapshot persistence and by a deferred database graph constraint.                                                                                                                     | CSV graph validation, snapshot validation, `db/tests/001_schema_smoke.sql`           |
| Dates and life status        | A death date cannot precede birth and cannot coexist with `is_deceased=false`; a death date implies deceased when the flag is omitted.                                                                                                | snapshot Zod refinements, CSV validation/property cases, database date columns       |
| CSV import                   | Import is owner/administrator-only, rate-limited, previewed before apply, mapped one-to-one, graph validated, and applied against the previewed tree version.                                                                         | CSV parser/draft/import handler tests, migration 033                                 |
| Snapshot concurrency         | Every mutation carries `expectedVersion` and a stable batch id. The tree row is locked, writes are serialized, successful snapshots retain parent/version metadata, and conflicts stop automatic persistence until explicit recovery. | family store activation/import tests, snapshot repositories, migrations 016 and 036  |
| Bilingual fallback           | A person with either English or Arabic content remains a valid named actor; display selects the requested language and falls back to the other. RTL remains driven by the i18n provider.                                              | activity label/projection tests and shared formatting                                |

## Characterized ambiguities

- The persisted model uses PostgreSQL `date`, so partial or uncertain genealogy dates are not a
  supported contract. CSV requires valid ISO dates. The general snapshot request currently accepts
  bounded date strings and relies on database casting for final validity; changing this to support
  partial dates requires an explicit product and schema decision.
- Deleting a male member may offer deletion of linked wives, but it is never automatic for protected
  or explicitly selected records. This is current UI policy, not a claim about genealogy semantics.
- Branch ancestry follows recorded parent links and the nearest active male-root branch. When source
  records are incomplete, the system preserves the recorded graph instead of inferring family policy.
